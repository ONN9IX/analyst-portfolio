# Бизнес-бриф: единая отчётность по продажам

> **Бизнес-сценарий DataBridge Solutions:** условный заказчик, открытые учебные данные.

## Исходный запрос

Условный руководитель коммерческого направления хочет видеть выручку, прибыль, средний чек и наиболее значимые категории товаров в одном отчёте. Финансовый отдел и отдел продаж должны использовать одинаковые определения показателей.

## Цели

1. Рассчитать согласованные показатели по 2 000 строкам входного набора.
2. Сравнить категории, регионы и сегменты покупателей.
3. Визуализировать важные результаты в BI.
4. Сформулировать ограничения анализа и вопросы к следующей выгрузке.

## Важные решения до начала работы

| ID | Вопрос | Выбранное правило | Ограничение |
|---|---|---|---|
| D-01 | Как считать выручку? | `SUM(Total_Sales)` | Скидка уже учтена в поле источника |
| D-02 | Как считать средний чек? | `SUM(Total_Sales) / COUNTD(Order_ID)` | Одна строка — один заказ в учебном CSV |
| D-03 | Что считать прибылью? | `SUM(Profit)` | Это поле данных, а не сверенная бухгалтерская прибыль |
| D-04 | Как считать уникальных покупателей? | `COUNTD(Customer_Name)` | Оценка по именам, устойчивого ID нет |
| D-05 | Можно ли определить ROI/ROAS? | Нет | Нет достоверного объединённого источника маркетинговых затрат и доходов |
| D-06 | Можно ли назвать прирост результатом изменений? | Нет | Нет эксперимента, причинно-следственный эффект не подтверждён |

## Acceptance criteria

- Скрипт Python повторяемо рассчитывает KPIs и отклоняет дубли `Order_ID`.
- SQL вычисляет revenue из того же столбца `Total_Sales`.
- DataLens демонстрирует те же базовые показатели без фильтров.
- В отчёте отдельно указаны гипотезы для следующего исследования, а не выдуманные «победы».
- Пользователь может скачать исходный CSV и проверить цифры.

## Out of scope

Платежи, налоги, CRM-интеграции, атрибуция маркетинговых каналов и реальные договоры.
