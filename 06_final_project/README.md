# E-commerce 360 — итоговый проект Data Analyst

## Бизнес-задача
Провести end-to-end анализ e-commerce данных за **2023–2025** и определить, какие категории и регионы формируют выручку и прибыль, насколько устойчива клиентская база и какие направления требуют дополнительной проверки.

## Dataset
`data/global_ecommerce_sales.csv` — 2 000 заказов, 02.01.2023–31.12.2025.

## Проверенные KPI
| Метрика | Значение |
|---|---:|
| Orders | 2 000 |
| Customers | 1 534 |
| Units | 7 115 |
| Revenue | 484 559.34 |
| Profit | 158 872.32 |
| Profit Margin | 32.79% |
| AOV | 242.28 |
| Shipping Cost | 25 804.24 |
| Repeat Customer Rate | 25.55% |

## Что обнаружено
**Furniture** — крупнейшая категория по Revenue: **256 274,68**, то есть около **52,9%** общей выручки. При этом её margin **31,67%** ниже Technology и Clothing & Accessories.

**Clothing & Accessories** имеет наиболее высокую category margin — **37,64%**, но значительно меньшую абсолютную выручку (**69 375,63**).

**Office Supplies** имеет наиболее низкую margin — **17,12%**. Это направление требует отдельной проверки структуры цен, скидок и затрат, но текущие данные не позволяют установить причину низкой маржинальности.

По регионам лидирует **Europe — 137 006,20**, затем **North America — 133 876,38**. Разница между ними относительно небольшая, поэтому данные не дают основания считать один регион принципиально сильнее другого без дополнительного анализа периода и продуктового микса.

Repeat Customer Rate по доступному `Customer_Name` составляет **25,55%**.

## Что можно сделать бизнесу дальше
- проверить причины низкой маржинальности Office Supplies на уровне товаров, скидок и затрат;
- изучить, можно ли масштабировать более маржинальные позиции Clothing & Accessories без потери unit economics;
- декомпозировать Furniture по товарам: категория создаёт более половины Revenue и поэтому особенно влияет на общий результат;
- исследовать retention/repeat behavior на данных со стабильным `customer_id`;
- дополнить анализ маркетинговыми каналами и acquisition cost, если такие данные станут доступны.

Это **направления дальнейшего анализа**, а не причинные утверждения: текущий dataset не позволяет доказать, почему наблюдаемые различия возникли.

## Ограничения
- `Customer_Name` используется как доступный идентификатор клиента вместо стабильного `customer_id`;
- нет marketing spend / acquisition channel;
- нет экспериментальной постановки;
- наблюдательные агрегаты не доказывают причинность.

## Воспроизводимость
```bash
pip install -r requirements.txt
python analysis.py
```

Скрипт формирует CSV в `results/`: KPI, месячную динамику, категории, регионы и клиентов.
